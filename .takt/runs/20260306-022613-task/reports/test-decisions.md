# 決定ログ

## 1. xunit 2.9.3 を使用（xunit v3 ではなく）
- **背景**: プロジェクトは net10.0 だが、xunit v3 はプレビュー段階であり `Assert.Skip()` の挙動が安定しない
- **検討した選択肢**: xunit 2.9.3 / xunit v3（preview）
- **理由**: グローバル NuGet キャッシュに xunit 2.9.3 が存在し復元可能であることを確認済み。2.x の `[Fact(Skip = "...")]` で条件スキップの要件を満たせる

## 2. 統合テストを `[Fact(Skip = "...")]` で静的マーク
- **背景**: `samples/Samples.sln` と CLI バイナリは implement フェーズまで存在しない
- **検討した選択肢**: (a) 統合テストを書かない、(b) ランタイムで `SkipException` を throw、(c) `[Fact(Skip = "...")]` で静的スキップ
- **理由**: xunit 2.x はランタイムスキップを標準サポートしない。`[Fact(Skip = "...")]` ならビルドが通り CI 上も「スキップ」として記録される。implement フェーズ完了後に Skip 属性を外すだけでパスに転換できる

## 3. スタブプロジェクトを作成しない
- **背景**: `Roslyntic.Core` 等が存在しないためビルドが失敗する
- **検討した選択肢**: (a) 型定義のみのスタブプロジェクトを作成してビルドを通す、(b) スタブなしでテストを書きビルド失敗を許容する
- **理由**: 「プロダクションコードは作成しない」の制約に従い (b) を採用。残存エラーはすべて CS0234/CS0246/CS0103（未作成プロジェクト参照）のみで、テストコード自体の構文エラーはゼロ。これは TDD で想定された「赤フェーズ」の正常な状態

## 4. `DiagnosticSorter` を独立した静的クラスとして設計
- **背景**: 決定論的ソートは Core パイプラインと Sarif 出力前の複数箇所で必要
- **検討した選択肢**: (a) `IEnumerable<Diagnostic>` 拡張メソッド、(b) 独立した `DiagnosticSorter` 静的クラス
- **理由**: 静的クラスは依存注入不要で単体テストが簡潔になり、呼び出し箇所での意図が明示的になる
